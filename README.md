# grpcMUD

`grpcMUD` is a multiplayer arena-style MUD built on top of a bidirectional gRPC stream.
The server is authoritative and tick-based, and the current client is a 3D renderer with an
ImGui HUD for commands and chat.

## Features

- Bidirectional gRPC gameplay stream (`Play`)
- Tick-based simulation with one gameplay command allowed per tick
- PvP and NPC combat with melee and ranged attacks
- Guard mechanic and directional combat
- Knockout + timed respawn flow
- Proximity chat (`say`) with distance-based messaging
- Local view updates including visible squares, actors, and first-person cells
- Persistent world storage (JSON or binary protobuf)

## Tech Stack

- C++23
- CMake (3.21+)
- vcpkg (via submodule)
- gRPC + Protobuf
- SDL3 + ImGui
- Frame engine (submodule at `external/frame`)

## Repository Layout

- `proto/` Protobuf and gRPC service definitions
- `server/` gRPC server, world simulation, combat, persistence
- `client/` 3D client, HUD/input, networking session
- `asset/` shaders, textures, generated mesh/cache assets
- `data/` persisted world data
- `external/` submodules (`vcpkg`, `frame`)

## Quick Start (Windows / PowerShell)

### 1. Clone and init submodules

```powershell
git clone <your-fork-or-repo-url>
cd grpcMUD
git submodule update --init --recursive
```

### 2. Configure and build

```powershell
cmake --preset windows
cmake --build --preset windows-debug
```

Debug executables are generated at:

- `build/windows/server/Debug/grpcmud_server.exe`
- `build/windows/client/Debug/grpcmud_client.exe`

## Running

### Start server

```powershell
.\build\windows\server\Debug\grpcmud_server.exe
```

Server flags:

- `--map_file=<path>` default `data/world_state.json`
- `--autosave_seconds=<int>` default `60`
- `--tick_interval_ms=<int>` default `500`

Example:

```powershell
.\build\windows\server\Debug\grpcmud_server.exe --map_file=data/world_state.json --autosave_seconds=30 --tick_interval_ms=400
```

### Start client

```powershell
.\build\windows\client\Debug\grpcmud_client.exe --server_address=localhost:50051 --player_name=alice --render_api=vulkan
```

Client flags:

- `--server_address=<host:port>` default `localhost:50051`
- `--player_name=<name>` default empty (enter in HUD)
- `--render_api=<opengl|vulkan>` default `vulkan`

The client also accepts positional args:

- arg1 = server address
- arg2 = player name

Example:

```powershell
.\build\windows\client\Debug\grpcmud_client.exe localhost:50051 bob
```

## Gameplay Controls

- `W` / `S` move forward/backward
- `A` / `D` turn left/right
- `H` `J` `K` `L` vim-style aliases (`K` forward, `J` backward)
- `1` melee attack
- `2` ranged attack
- `3` guard
- `P` ping server
- `/` start slash command input
- `Enter` focus chat/command input
- `Esc` clear/unfocus chat input
- `Q` quit client

## Chat and Slash Commands

Text without a leading slash sends chat (`say`).

Supported slash commands:

- `/look`
- `/move forward`
- `/move backward`
- `/turn left`
- `/turn right`
- `/say <text>`
- `/guard`
- `/attack melee`
- `/attack ranged`
- `/ping`
- `/help`

## Networking Model

- Service: `mud.v1.MudService`
- RPC: `Play(stream ClientMessage) returns (stream ServerMessage)`
- Client sends: join/look/step/say/guard/attack/ping
- Server sends: join ack, command ack, world events, errors, pongs, ticks, local view updates

## Persistence

- Default world file is `data/world_state.json`
- Autosave runs on server interval and on shutdown
- If map extension is `.json`, data is saved as JSON
- Any other extension saves binary protobuf

## Notes for Development

- Protobuf and gRPC stubs are generated by CMake from files in `proto/`
- CMake presets currently target Visual Studio 2022 (`windows`, `windows-debug`, `windows-release`)
- Generated geometry OBJ files are written under `asset/model/` by the client scene builder
